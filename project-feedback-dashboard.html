Review Friction Visibility — Six-Tab Dashboard

Review friction in regulated work accumulates invisibly across feedback cycles, becoming visible only after delays have already escalated. This project makes that accumulation observable earlier — without collapsing reviewer judgment into automated outputs.

📋 Pilot study 👥 N=20 GMP practitioners 📊 Six-tab dashboard + TF-IDF 🛠 Streamlit + Python
📖 Background
What is review friction in GMP?
In regulated work, every deviation, CAPA, or change control document passes through multiple reviewers before closure. Each round produces feedback comments that submitters must address — often through repeated revision loops. Teams know a document is "still under review," but rarely have visibility into what type of comments are driving the delay, where bottlenecks are forming, or whether a loop is escalating across rounds. The friction is real but invisible until it has already accumulated.

01The problem — review friction accumulates invisibly
▼

In regulated environments, document review is critical but opaque. Deviation, CAPA, and related records pass through multiple reviewers — yet visibility into feedback burden, timing, and revision-loop formation is limited.

Teams know a document is "still under review," but not what type of comments are driving the delay, where bottlenecks are forming, or whether a loop is escalating across rounds.

Observed pain points:

  • Repeated revision loops difficult to observe as patterns
  • Feedback burden uneven across reviewers but hard to see
  • Small wording comments generated multi-day back-and-forth
  • Review process felt slow but source of friction remained unclear

The core problem is not delay itself — it is the lack of a shared operational view of that delay.

02The dashboard — six tabs of observability
▼

An interactive Python/Streamlit dashboard built on a synthetic review-workflow dataset (100 records: comment categories, review rounds, severity, turnaround time, reopening, reviewer role, document type). Each tab surfaces a different facet of review burden as observability tools, not decision-automation.

▸ Tab 01 · overview
Comment category distribution and turnaround by role surface uneven feedback burden across reviewer positions.
▸ Tab 02 · revision heatmap
Density visualization across review rounds — clusters of high revision rate indicate friction points before delays escalate.
▸ Tab 03–04 · checklist + classifier
Pre-review checklist supports immediate self-assessment; rule-based classifier categorizes comment types.
▸ Tab 05–06 · document journey + reviewer simulation
Document journey tracing surfaces revision loops across rounds; reviewer simulation explores load distribution scenarios.
03The pattern detection layer — TF-IDF clustering
▼

An additional layer using TF-IDF similarity clustering to identify recurring issue patterns across review history — multi-factor revision burden scoring and pattern summaries. This functions as an observability tool, not a decision-automation system: it surfaces clusters for reviewer interpretation rather than recommending actions.

▸ Pattern detection · TF-IDF clustering
Recurring issue clusters surfaced via TF-IDF similarity. Reviewers retain interpretive control — the system identifies patterns, not actions.
▸ AI orientation layer (conceptual)
Conceptual extension: the AI orientation layer explains what kind of cluster emerged and why, without claiming what action to take.
04Pilot study — N=20 evaluation
▼

Prototype evaluation session with N=20 QA/QC-experienced participants. Findings show role-differentiated utility across submitter and reviewer positions, with all participants anticipating reduced accountability asymmetry from friction visibility.

Key dissociation finding. Both components received equivalent final ratings (5.0/5) and equivalent adoption intent (20/20), but they arrived at those ratings through different pathways: the checklist via immediate legibility, the TF-IDF clustering via post-orientation interpretive trust.
Limitations. Same-team recruitment may have inflated usability ratings. Synthetic 100-record dataset is smaller than real review archives. Findings are observational and exploratory — they identify a productive distinction (immediate legibility ≠ endorsement) rather than a controlled effect size.
✓ What worked
  • Six-tab structure made friction observable across multiple facets
  • Checklist legible without explanation
  • Pattern detection reached equivalent trust after orientation
  • Both components anticipated to reduce reviewer-submitter asymmetry
⚠ Remaining friction
  • TF-IDF clustering required initial interpretive orientation
  • Synthetic data smaller than real review archives
  • Adoption intent ≠ adoption — long-term use untested
  • Reviewer simulation tab least developed conceptually
05What this revealed
▼

The strongest finding is a dissociation: immediate legibility ≠ endorsement. The checklist supported immediate comprehension and required no conceptual reorientation; the TF-IDF clustering layer required initial orientation to interpret in a way the dashboard's other components did not. Both ultimately reached 5.0/5 — but through distinct cognitive pathways.

"Visibility tools must address not only interface design but the conceptual work of making patterns interpretable to practitioners who have not previously had this kind of view."

The Layer 3 design move is to make coordination friction observable before it escalates into formal deviation — distributing review burden visibly rather than letting it accumulate invisibly. Productive tension: the more a system preserves human judgment by withholding recommendations, the more it requires conceptual orientation to use.
