Operational tool · Deployed

Task Manager

Daily task assignment and tracking across the QC team — with a workload heatmap embedded in the calendar, and certification logic embedded directly in the assignment UI so uncertified analysts can't be assigned tests they're not authorized to run.

The problem

Two failure modes: saying yes to too much work, and losing analyst schedules to handover gaps.

QC teams take in external testing requests on an ongoing basis. The fundamental question is always: can we actually handle this in the timeline they want? Without a clear picture of who's doing what for the next few months, the safest-feeling answer is "yes" — and then the team discovers later that capacity was already over-allocated. The cost shows up as missed deadlines, rushed work, and analysts burning out quietly.

The other failure mode is invisible until it bites: analyst schedules live in their own heads. When an analyst leaves, transfers, or is out unexpectedly, the next-month schedule they were holding mentally goes with them. Handover documents help but rarely capture the operational detail. Tests fall through the gap.

Both problems share a root: capacity and workload are tacit — held in people's memories, not surfaced anywhere. The tool externalizes both, with the bonus that doing so makes a third structural requirement enforceable through the UI itself.

What it does

Capacity in the calendar, certification in the assignment logic.

Heatmap-in-calendar
Workload intensity lives directly in the calendar view — color depth shows how many tests run that day. "Where is this week tight?" answerable at a glance, not by mental aggregation across rows.
Certification embedded in assignment
In GMP environments, uncertified analysts must not be assigned tests they aren't authorized to run. The tool only shows certified analysts as assignable candidates per test type — regulatory compliance built into the UI itself.
Analyst-side schedule view
Each analyst sees their own monthly schedule — what they're assigned, what's coming, what's overdue. Handovers become structural rather than tacit.
Workload-by-person
A separate workload view shows capacity per analyst. Catches imbalances early — useful for deciding whether to accept new external work or push back on timelines.
Overdue surfacing
"3 days over," "D-2," "D-12" status pills make timing visible at a glance — no scanning through deadlines column by column.
Test-level granularity
Tests tracked individually — not just projects. Multi-method work stays legible; nothing hides inside a project block.
Why certification belongs in the assignment UI

Compliance enforced through interface, not through reminder.

In a GMP environment, certification isn't optional — an uncertified analyst running a test method is a serious quality and regulatory issue. The usual response is training, reminders, audit checks. All necessary, but they all rely on memory or post-hoc review.

Design principle

Putting the certification matrix inside the assignment logic itself shifts the safeguard from "please remember the rules" to "the rule is structurally impossible to violate." If the analyst's name doesn't appear in the candidate dropdown, the wrong assignment can't happen — not because someone caught it later, but because the system never offered it in the first place. Regulatory compliance becomes a property of the interface, not a property of vigilance.

In daily use

Deployed to the team I work with.

Used daily by both managers (workload, certification, all-tests view) and analysts (their own schedule and overdue items). The same tool serves two different roles by surfacing different views of the same underlying data.

Deployed

Used by 14 analysts and the QC management team. Iterated across multiple versions in response to operator feedback. Includes reproduction guide and team training documentation — including the certification-matrix maintenance procedure so future admins keep regulatory compliance enforced.
